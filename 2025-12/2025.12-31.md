# Mutable vs Immutable: Python의 메모리 관리 모델
- # 1. 프로그램 실행의 시작: 하드웨어와 메모리

### **[Step 1]**

- 프로그램이 실행되기 전, 코드와 데이터가 보조기억장치(SSD/HDD)에 파일 형태로 영구 보관되는 단계입니다.

### **[Step 2]**

- 사용자가 프로그램 실행 명령을 내리면, 운영체제가 파일을 읽어 속도가 매우 빠른 주기억장치(RAM)로 복사합니다. 이 과정이 완료되어야 프로그램은 비로소 '프로세스'가 되어 CPU와 소통할 준비를 마치게 됩니다.

### **[Step 3]**

- 운영체제가 RAM에 올라온 프로그램을 위해 용도별로 4개의 구역(Code, Data, Heap, Stack)을 나눕니다.
- 여기서 용도별로 나눠진 구역이 “메모리”

### **[Step 4]**

- CPU가 RAM에서 명령어를 가져와(**Fetch**), 내용을 분석하고(**Decode**), 실제로 연산하는(**Execute**) 단계입니다.

- ⇒ 프로그램 실행

- **운영체제의 메모리 할당:** 프로그램은 운영체제로부터 크게 4가지 영역을 할당 받습니다.
    - **Code 영역:** 프로그램의 실행 코드가 저장되는 곳. ⇒ **실행 코드 저장 공간**
    - **Data 영역:** 전역 변수나 정적 데이터가 저장되는 곳. ⇒ **데이터 저장 공간**
    - **Stack 영역:** 함수 호출 시 생성되는 지역 변수, 매개변수, 복귀 주소가 저장되는 곳. ⇒ **함수 저장 공간**
    - **Heap 영역:** 필요에 따라 동적으로 할당되는 공간(파이썬 객체들이 사는 곳).

### **코드(Code) 영역**

- **프로그램의 실행 코드가 저장**되는 메모리 영역

### **데이터(Data) 영역**

- **변수, 상수 등의 데이터**가 저장되는 메모리 영역

### **스택(Stack) 영역**

- **함수의 호출과 관련된 데이터가 저장**되는 메모리 영역

### **힙(Heap) 영역**

- 동적으로 할당된 메모리, 즉 **런타임에 필요한 메모리가 동적으로 할당**되는 메모리 영역

## **메모리 할당 방법**

### **변수 선언과 메모리 할당**

파이썬에서 **변수를 선언할 때, 해당 변수에 저장될 값의 메모리 공간이 할당**된다.

변수는 단지 이름일 뿐이며, **변수가 실제 값을 가리키는 메모리 주소를 참조**한다.

예를 들어, x = 10을 실행하면 정수형 10의 메모리가 할당되고, 변수 x는 이 메모리 주소를 가리키게 된다.

# 2. 파이썬의 메모리 구조

## 1. 파이썬의 메모리 구조 (Stack vs Heap)

파이썬(CPython)은 메모리를 크게 두 영역으로 나누어 관리합니다.

→ python memory manager가 python의 모든 객체, 데이터 구조를 프라이빗 Heap에 저장

![](https://blog.kakaocdn.net/dna/bstohp/btrHrNc7iTF/AAAAAAAAAAAAAAAAAAAAAJVhArxz6ZAAe0EboWZ-V2KxyQ9P78mHj18Ke4F7SqzI/img.png?credential=yqXZFxpELC7KVnFOS48ylbz2pIh7yKj8&expires=1767193199&allow_ip=&allow_referer=&signature=I8JWjLmgwP4z0u%2Fq50QzMBDpzow%3D)

- Stack
    - 이미 할당되어 있는 공간 사용 (**저장**되는 메모리 영역)
    - 참조자 저장 (Reference)
- Heap
    - 사용자가 할당해서 사용하는 공간 (동적으로 할당된 메모리)
    - 객체 저장

---

## 2. 변수는 **이름표(참조)일 뿐이다** (Call by Object Reference)

파이썬의 변수 할당 방식은 **"Call by Object Reference"** 또는 "Call by Assignment"라고 불립니다.

- 변수는 값을 직접 담는 바구니가 아니라, 메모리 어딘가(Heap)에 있는 객체를 가리키는 **포인터**(이름표)입니다.
- **id() 함수 활용:** 객체의 고유한 메모리 주소를 반환합니다. `id(a) == id(b)`라면 두 변수는 같은 객체를 바라보고 있는 것입니다.

---

## 3. Mutable(가변) vs Immutable(불변) 객체

이 구분을 이해해야 왜 `a = b`를 했을 때 결과가 달라지는지 알 수 있습니다.

| **구분** | **해당 타입** | **특징** |
| --- | --- | --- |
| **Immutable** | `int`, `str`, `tuple`, `float` | 객체 생성 후 **값 변경 불가**. 변경 시 새로운 객체 생성. |
| **Mutable** | `list`, `dict`, `set` | 객체 생성 후 **내부 값 변경 가능**. 주소값 유지. |

### Case 1: Immutable (a = 10일 때)  ⇒ **Call by Value(값에 의한 호출)**

1. `a = 10`: Heap 영역에 `10` 객체 생성, `a`가 이를 가리킴.
2. `b = a`: `b`도 `10` 객체를 같이 가리킴 (`id` 동일).
3. `b = b + 1`: `10`은 불변이므로 수정할 수 없음. 힙에 **새로운 `11` 객체**를 만들고 `b`가 이를 가리키게 함.
4. **결과:** `a`는 여전히 `10`을 가리키므로 변하지 않음.

---

- 변수가 가진 **'값' 자체를 복사**해서 함수에 전달합니다.
- 함수 내부에서 값을 아무리 수정해도, 함수 밖의 원래 변수에는 **아무런 영향이 없습니다.**
- = GitHub 클론

### Case 2: Mutable (a = [1, 2, 3]일 때 - Shallow Copy) ⇒ Call by Reference (참조에 의한 호출)

1. **`a = [1, 2, 3]`**: Heap 영역에 리스트 객체 생성, **`a`**가 이를 가리킴.
2. `b = a`: `b`도 동일한 리스트 객체 주소를 가짐.
3. `b.append(4)`: 리스트는 가변 객체이므로 **같은 주소의 메모리 내부**를 수정함.
4. **결과:** `a`와 `b`는 같은 웹 페이지에 접속했고 내부만 바뀐 느낌
    
    ⇒  `a`를 확인해도 `[1, 2, 3, 4]`가 나옴.
    

---

- 변수가 저장된 '메모리 주소(참조)'를 직접 전달합니다.
- 함수 내부에서 값을 수정하면, 같은 주소를 바라보고 있는 **함수 밖의 원래 변수도 같이 수정됩니다.**
- = 권한이 전체 허용된 노션 링크

---

## 4. 파이썬의 메모리 관리 기법

### 참조 카운팅 (Reference Counting)

- 객체가 참조될 때마다 카운트가 증가하고, 참조가 해제(변수 삭제 등)되면 감소합니다.
- 카운트가 **0**이 되는 순간, 메모리에서 즉시 해제됩니다.

### 가비지 컬렉션 (Garbage Collection)

- **순환 참조**(A가 B를, B가 A를 참조하는 경우)는 참조 카운트가 0이 되지 않아 메모리 누수를 일으킵니다.
- 파이썬 GC는 '세대별 관리'와 '순환 참조 탐지'를 통해 이를 주기적으로 해결합니다.

### 얕은 복사(Shallow) vs 깊은 복사(Deep)

- **얕은 복사 (`copy()`, `[:]`):** 새 리스트는 만들지만 내부 요소는 기존 주소를 참조합니다. (중첩 리스트 수정 시 문제 발생)
- **깊은 복사 (`copy.deepcopy()`):** 내부의 모든 객체까지 새롭게 복제하여 완벽하게 독립적인 개체를 만듭니다.

---

## 5. 메모리 효율을 위한 팁

1. **Slot 사용:** 클래스에 `__slots__`를 정의하면 인스턴스마다 생성되는 `__dict__`를 방지해 메모리를 40~50% 절약할 수 있습니다.
2. **Generator 활용:** `yield`를 사용하면 데이터를 한 번에 메모리에 올리지 않고 필요할 때만 생성(Lazy Evaluation)하여 대용량 처리에 유리합니다.
3. **String Interning:** 짧은 문자열이나 식별자는 파이썬이 내부적으로 재사용하여 메모리를 최적화합니다.
4. **Weakref(약한 참조):** 참조 카운트를 올리지 않고 객체를 참조하게 하여, 캐시 등을 구현할 때 GC가 자유롭게 메모리를 수거할 수 있도록 돕습니다.
